# Что сделано в проекте

Сводка по состоянию на 11 сентября 2026. Технические подробности и инструкции
по настройке — в [README.md](README.md); здесь то, чего в нём нет: почему
сделано именно так и на какие грабли уже наступили.

---

## Коротко

Личный бот-инбокс: пересылаешь сообщение в Telegram — оно становится страницей
в базе Notion «Telegram Inbox».

| | |
|---|---|
| Бот | [@notion_fletch_telegram_bot](https://t.me/notion_fletch_telegram_bot) |
| Сервис | https://telegram-notion-bot-t9b8.onrender.com |

| Тесты | 153, все зелёные |

## Что работает

- **Сохранение** текста, ссылок, фото, видео, файлов, голосовых
- **Архив видео** — видео уезжает в приватный канал Telegram, в заметке Notion
  остаётся ссылка на него; туда же падает всё, что не влезло в лимит Notion
- **Форматирование** — жирный, курсив, зачёркнутый, код, ссылки, цитаты,
  блоки кода с подсветкой языка
- **Статьи по ссылкам** — заголовок, описание и полный текст в тело страницы
- **Источник** — канал, чат или автор, плюс ссылка на исходное сообщение
- **Дедупликация** — повторная пересылка не создаёт вторую запись
- **Альбомы** — несколько фото одним постом становятся одной записью
- **Кнопки категорий** приходят под каждой записью
- **Команды** `/start`, `/help`, `/ping`, `/id`, `/last`
- **Деплой** — автоматический на каждый push в `main`

## Что не работает

**Простановка категории по кнопке.** Нажатие отвечает «Notion не принял
категорию». В логах Render:

```
Notion 404 [object_not_found]: Could not find page with ID:
3d7de3e0-016c-8107-a8b1-e7cce7fa3154
```

Notion не находит страницу, на которую ссылается кнопка. При этом та же
операция, вызванная вручную для существующей записи, проходит без ошибок —
значит, дело не в самой установке свойства.

Две версии, ни одна не проверена:
1. Кнопки нажимались под старым сообщением, чья страница уже удалена (в ходе
   отладки удалялись тестовые записи).
2. В `callback_data` уезжает не тот идентификатор страницы.

Проверять здесь: `choose_category` и `_keyboard` в
[bot/handlers.py](bot/handlers.py), `SaveResult.page_id` в
[bot/pipeline.py](bot/pipeline.py).

## Что не проверено на живом боте

Альбом из нескольких фото, файл до 5 МБ и больше 5 МБ, голосовое, повторная
пересылка. Всё это покрыто тестами на заглушках, но вживую руками не
прогонялось — мешали обрывы связи, из-за которых ответы бота не доходили.

Сюда же архив видео: логика закрыта тестами, но живьём нужен настоящий канал —
проверить `/id` в канале, `/ping`, ролик меньше и больше 20 МБ и случай, когда
бот не админ.

## Принятые решения

| Решение | Выбор | Почему |
|---|---|---|
| Захват сообщений | Пересылка боту в личку | Обычный Bot API, без userbot и рисков с ToS |
| Хранилище | Одна база «Telegram Inbox» | Фильтры, поиск и представления по всем записям сразу |
| AI-обработка | Нет | Заголовок выводится эвристикой, внешних LLM не нужно |
| Категории | Кнопки после сохранения | Не нажал — запись всё равно цела; ничего не теряется |
| Стек | Python 3.12 + aiogram 3.31 | Зрелая библиотека, Python уже стоял в системе |
| Хостинг | Render, Франкфурт | У сервера прямой доступ к Telegram — главная причина переезда |
| Режим | Вебхук | На бесплатном плане Render нет фонового воркера |
| Дедупликация | Ключ в свойстве Notion | Эфемерный диск Render не переживёт своей БД |
| Хранилище видео | Приватный канал Telegram | Пересылка не качает файл — единственный способ сохранить ролик больше 20 МБ |

Изначально категорий не планировалось — добавлены позже по ходу работы.

## Грабли, на которые уже наступили

Самая ценная часть документа: всё это выяснилось только на практике.

### Смещения Telegram считаются в UTF-16

`offset` и `length` сущностей сообщения — в кодовых единицах UTF-16, а не в
символах Python. На кириллице совпадает, но любой эмодзи вне BMP занимает две
единицы, и разметка съезжает: жирный шрифт и ссылки встают не на те слова.
[bot/formatting.py](bot/formatting.py) строит карту смещений; это закрыто
тестами, потому что глазами на коротком примере поломку не заметить.

### У баз Notion появились data sources

С версии API 2025-09-03 страница создаётся с родителем `data_source_id`, а не
`database_id`, и запросы уходят в `/v1/data_sources/...`. Клиент один раз при
старте резолвит идентификатор источника по идентификатору базы.

### Форма блока с файлом в документации описана противоречиво

Проверено на живом API скриптом [scripts/smoke_notion.py](scripts/smoke_notion.py):
работает `{"type": "file_upload", "file_upload": {"id": ...}}`. Скрипт умеет
пробовать обе формы и говорить, какая принята.

### Видео через Bot API не скачать, зато можно переслать

`getFile` отвечает «file is too big» на всё, что больше 20 МБ, — обычное видео
через него получить нельзя, и никакие настройки этого не меняют. Но
`forwardMessage` файл не качает: Telegram копирует его у себя. Отсюда и решение
хранить видео в приватном канале — оно обходит оба потолка сразу, и телеграмный,
и нотионовский, ценой того, что ссылка открывается только у подписчиков канала.

Побочный эффект, который стоит помнить: канал, запретивший пересылку своих
постов (`has_protected_content`), архиву недоступен — `forwardMessage` вернёт
ошибку, и бот откатится на старый путь с заметкой.

### Лимит на размер файла лучше спрашивать у API

`GET /v1/users/me` возвращает `max_file_upload_size_in_bytes`. Сейчас это 5 МБ
(бесплатный план); при переходе на платный бот сам начнёт грузить больше без
правок кода. Отдельный потолок — 20 МБ у Bot API на скачивание, его не обойти.

### trafilatura склеивает слова в заголовке

Она собирает заголовок из вёрстки страницы, где слова разнесены по соседним
элементам: `obscura.sh` давал «Give every agent**its** own browser». Теперь
источник — `og:title` и `<title>`, trafilatura осталась запасным вариантом.
Заодно отрезается имя сайта («Всё подряд / Хабр» → «Всё подряд»), но только при
точном совпадении, чтобы не покалечить «A/B тесты».

### callback_data обрезается молча

Telegram режет строку длиннее 64 байт без ошибки. Формат `c:<индекс>:<32 hex>`
занимает 37 байт; на это есть тест, чтобы будущие правки не сломали кнопки
незаметно.

### Секрет вебхука от Render не проходит проверку Telegram

Telegram принимает в `secret_token` только `A-Z`, `a-z`, `0-9`, `_` и `-`.
Render генерирует значение по своим правилам — первый деплой упал с
`secret token contains illegal characters`. Бот приводит значение к
допустимому виду сам: непригодное заменяется своим sha256, который стабилен
между перезапусками и не раскрывает исходную строку.

### aiogram складывает таймаут сессии с числом

`int(session.timeout + polling_timeout)` — если положить в это поле объект
`ClientTimeout`, опрос падает на первом же цикле. Число должно остаться
числом, а полноценный таймаут подставляется в момент запроса.

### Render требует карту даже на бесплатном плане

Привязка карты запрашивается до создания любого сервиса — временная
авторизация на $1 через Stripe.

### Панель Render недоступна из России, домен приложений — доступен

`render.com` и `dashboard.render.com` не открываются, а `*.onrender.com`
работает напрямую. То есть VPN нужен для настройки и логов, но не для работы
бота. Любопытная деталь: `community.render.com` открывается, хотя сидит на тех
же IP, что и заблокированная панель — фильтрация идёт по имени хоста в TLS, а
не по адресу.

## История: борьба со связью

Больше половины работы ушло не на функциональность, а на устойчивость. Полезно
помнить, если что-то подобное повторится.

С домашней сети связь с `api.telegram.org` рвалась минутами. `getUpdates`
переживал обрывы (его соединение уже установлено и лежит в пуле), а любой
исходящий вызов требовал нового соединения и падал. Симптом со стороны
пользователя: сообщение сохраняется в Notion, но ответ с кнопками не приходит.

Что было сделано по шагам:

1. **Автоповторы всех вызовов Bot API** ([bot/session.py](bot/session.py)),
   отдельно обрабатывается флуд-контроль Telegram.
2. **Сбой на вложении перестал ронять запись целиком** — раньше сетевая ошибка
   на `getFile` уносила всё сообщение; теперь текст сохраняется, а на месте
   файла остаётся заметка с причиной.
3. **Ограничена фаза подключения** (10 с отдельно от общего лимита) — сорванная
   попытка стоила минуту, и четыре повтора съедали четыре минуты.
4. **Служебное «Сохраняю…» убрано с критического пути** в отдельную задачу и
   лишено повторов: если оно не ушло сразу, догонять его нельзя — приедет
   бессмысленным и повиснет на экране.
5. **Бот перестал падать от обрыва на старте** — проверочный `getMe` сделан
   необязательным.
6. **Доставка ответа растянута** паузами 15/30/60/120/180/300 секунд в фоне:
   запись уже сохранена, ответу надо просто дождаться окна связи.
7. **Команда `/last`** — спасательный круг: последняя запись с кнопками
   категорий, если ответ всё-таки не дошёл.
8. **Переезд на Render** — окончательное решение проблемы.

Первые семь пунктов не пропали даром: они делают бота живучим на любом
хостинге. Но корень был в сети, и снялся он только переездом.

## Эксплуатация

### Проверить, что бот жив

```bash
curl https://telegram-notion-bot-t9b8.onrender.com
```

Ответ `ok`. Первый запрос после простоя идёт до минуты — контейнер просыпается.

В самом боте: `/ping` покажет связь с Notion и текущий лимит на файл.

### Логи

Панель Render → сервис `telegram-notion-bot` → **Logs**. Только через VPN.

### Запустить локально

```bash
cd "C:\Claude\Notion-бот"
```

```bash
python -m bot.main
```

Читает `.env`, где `MODE=polling`. Важно: одновременно с работающим вебхуком на
Render локальный бот запускать нельзя — Telegram отдаёт обновления только
одному получателю.

### Тесты

```bash
python -m pytest -q
```

### Выкатить изменения

Push в `main` — Render пересоберётся сам.

## Что стоит сделать дальше

По убыванию пользы:

1. **Починить кнопки категорий** — единственное, что сейчас не работает.
2. **Прогнать вживую** альбом, файлы, голосовое, повторную пересылку.
3. **Поставить пинг** на [uptimerobot.com](https://uptimerobot.com), интервал
   10 минут — чтобы сервис не засыпал и первое сообщение не ждало минуту.
   Бесплатных 750 часов Render хватает на месяц непрерывной работы.
4. **Сбросить токен Notion** — он был виден на скриншоте в переписке. Кнопка
   сброса на странице интеграции, новое значение вписать в переменные Render и
   в локальный `.env`.
