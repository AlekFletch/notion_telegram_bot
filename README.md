# Telegram → Notion

Личный бот-инбокс: пересылаешь ему сообщение в Telegram — оно становится
отдельной страницей в базе Notion «Telegram Inbox».

Что сохраняется:

- текст с форматированием — жирный, курсив, зачёркнутый, `код`, ссылки,
  цитаты, блоки кода с подсветкой языка;
- фото, голосовые, документы (в пределах лимитов, см. ниже);
- видео, кружочки и гифки — в канал-архив, а в заметку ссылка на них
  (см. «Архив видео»);
- посты из Instagram и Facebook по ссылке — вложения уезжают в архив,
  подпись и автор в заметку;
- альбом из нескольких фото — одной записью, а не пятью;
- по ссылке из сообщения — заголовок, описание и текст статьи;
- источник: канал, чат или автор, плюс ссылка на исходное сообщение.

Повторная пересылка того же сообщения дубль не создаёт.

## Категории

Под каждой сохранённой записью бот показывает кнопки с категориями. Нажал —
категория проставилась в Notion, у кнопки появилась галочка. Передумал — нажал
другую, значение перезапишется. Не нажал вовсе — запись всё равно сохранена,
разберёшь потом в самом Notion.

Список категорий живёт в [bot/categories.py](bot/categories.py). Если правишь
его, приведи в соответствие варианты свойства «Категория» в базе — Notion
отклонит значение, которого нет в схеме.

В базе есть доска **«По категориям»** с группировкой — удобно разбирать
накопившееся.

## Быстрый старт

### 1. Токен бота

Написать [@BotFather](https://t.me/BotFather) → `/newbot` → придумать имя →
скопировать токен вида `123456789:AA...`.

### 2. Интеграция Notion

1. Открыть [notion.so/my-integrations](https://www.notion.so/my-integrations) →
   **New integration**.
2. Тип — **Internal**, воркспейс — свой.
3. Скопировать **Internal Integration Secret** (начинается с `ntn_`).

### 3. Дать интеграции доступ к базе

Это самый пропускаемый шаг. Без него бот получит 404 на своей же базе.

Открыть страницу [**Telegram Inbox**](https://app.notion.com/p/3d7de3e0016c811a81ade80b1a3fe2ca)
→ меню **⋯** в правом верхнем углу → **Connections** → выбрать свою интеграцию.

### 4. Настроить `.env`

```bash
cp .env.example .env
```

Заполнить `TELEGRAM_BOT_TOKEN` и `NOTION_TOKEN`. `NOTION_DATABASE_ID` уже
проставлен. `ALLOWED_USER_IDS` пока оставить пустым.

### 5. Проверить связь с Notion

```bash
python -m pip install -r requirements.txt
```

```bash
python -m scripts.smoke_notion
```

Скрипт создаст в базе тестовую запись с картинкой и закладкой и напечатает
ссылку на неё. Если что-то не так — скажет, что именно. Запись потом можно
удалить.

### 6. Запустить локально

```bash
python -m bot.main
```

Отправить боту `/start` — он ответит твоим Telegram ID. Вписать его в
`ALLOWED_USER_IDS` в `.env` и перезапустить. После этого бот будет отвечать
только тебе, а всем остальным — вежливо отказывать.

### 7. Настроить архив видео

Шаг необязательный, но без него видео крупнее 20 МБ сохранить нельзя: Bot API
такие файлы боту просто не отдаёт. Пересылка это ограничение обходит — Telegram
копирует файл у себя, ничего не скачивая.

1. Создать **приватный канал** (Telegram → Новый канал → Частный).
2. Добавить туда бота **администратором** с правом публиковать сообщения.
3. Написать в канале `/id` — бот ответит идентификатором вида `-100…`.
4. Вписать это значение в `ARCHIVE_CHAT_ID` и перезапустить бота.

`/ping` после этого покажет название канала. Если архив не настроен, бот
работает как раньше, только жалуется на размер вместо видео.

### 8. Cookies для Instagram

Тоже необязательно — но без cookies Instagram боту не отдаст ничего. Проверено:
на анонимный запрос он возвращает 200 и пустую JS-оболочку без единого
мета-тега, а yt-dlp получает «Instagram sent an empty media response».
Facebook и прочие сайты чаще отдаются и без логина.

1. Поставить в браузер расширение, которое экспортирует cookies в формате
   Netscape (например, «Get cookies.txt LOCALLY»).
2. Залогиниться в Instagram, экспортировать cookies в файл `cookies.txt`.
3. Render → сервис → **Environment** → **Secret Files** → **Add file**,
   имя `cookies.txt`, содержимое — из файла.
4. В переменную `SOCIAL_COOKIES_FILE` вписать `/etc/secrets/cookies.txt`.

Локально просто указать в `SOCIAL_COOKIES_FILE` путь к файлу на диске.

Что важно понимать:

- cookies дают серверу полный доступ к аккаунту и со временем протухают —
  тогда их надо выгрузить заново;
- Instagram может счесть обращения с чужого IP подозрительными и
  заблокировать аккаунт. Разумно завести для этого отдельный аккаунт;
- скачивание через yt-dlp нарушает условия использования Instagram.

Без cookies бот не сломается: сохранит ссылку и напишет в заметке, что нужна
авторизация.

## Деплой на Render

Бот развёрнут: **https://telegram-notion-bot-t9b8.onrender.com**

Порядок, если придётся повторить:

1. Залить проект в репозиторий GitHub (`.env` в него не попадёт — он в
   `.gitignore`).
2. На [render.com](https://render.com) → **New** → **Blueprint** → указать
   репозиторий. Render прочитает `render.yaml` и создаст web-сервис.
3. В появившейся форме заполнить `TELEGRAM_BOT_TOKEN`, `NOTION_TOKEN`,
   `NOTION_DATABASE_ID`, `ALLOWED_USER_IDS`. `MODE=webhook` и
   `WEBHOOK_SECRET` подставятся сами.
4. **Deploy Blueprint**. Адрес вебхука бот выставит сам из
   `RENDER_EXTERNAL_URL`.

Дальше деплой идёт автоматически на каждый push в `main`.

### Что выяснилось на практике

**Карта обязательна даже для бесплатного плана.** Render просит привязать её
до создания любого сервиса — временная авторизация на $1 через Stripe.

**Секрет вебхука Render генерирует по своим правилам**, и они шире того, что
принимает Telegram (только `A-Z`, `a-z`, `0-9`, `_`, `-`). Первый деплой упал с
`secret token contains illegal characters`. Бот теперь сам приводит значение к
допустимому виду — см. `_normalize_secret` в [bot/config.py](bot/config.py).

**Панель `render.com` может быть недоступна из России**, тогда как домен
приложений `*.onrender.com` открывается напрямую. То есть VPN нужен для
настройки и логов, но не для работы бота и не для проверки сервиса.

### Чтобы сервис не засыпал

Бесплатный план усыпляет сервис после 15 минут без запросов, и первое сообщение
после простоя обрабатывается с задержкой около минуты, пока контейнер
просыпается.

Лечится бесплатным пингом: на [uptimerobot.com](https://uptimerobot.com)
создать HTTP(s)-монитор на адрес сервиса с интервалом 10 минут. Бесплатных
750 часов Render как раз хватает на месяц непрерывной работы.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | Приветствие; в режиме настройки показывает твой Telegram ID |
| `/help` | Справка |
| `/ping` | Проверить связь с Notion и архивом, показать лимит на размер файла |
| `/id` | Показать твой Telegram ID; в канале — ID канала |

## Лимиты и что с ними делать

| Ограничение | Откуда | Поведение бота |
|---|---|---|
| Файл > 5 МБ | Free-план Notion | Уходит в канал-архив, в заметке ссылка; без архива — заметка с причиной |
| Файл > 20 МБ | Bot API Telegram | Скачать невозможно; спасает только архив — пересылка не качает файл |
| Видео любого размера | — | Всегда в канал-архив, скачивание не пробуется |
| Пост Instagram | Требует логина | Без cookies — только ссылка и пометка в заметке |
| Вложение поста > 50 МБ | Bot API Telegram | Бот столько не отправит; в заметке пометка |
| Пейволл, JS-рендеринг | Сайт статьи | Сохраняются заголовок, описание и ссылка |
| Скрытый автор пересылки | Приватность Telegram | Источник — «Скрытый отправитель» |

Лимит Notion бот узнаёт у API при старте (`/ping` его показывает). Перейдёшь
на платный план — начнёт грузить файлы до 20 МБ без правок кода.

Ссылка на оригинал строится только для сообщений из каналов: для публичных —
обычная `t.me/канал/123`, для приватных — `t.me/c/…`, которая откроется у тебя
как у подписчика. Для пересылок из личных чатов постоянной ссылки не
существует в принципе.

## Как это устроено

```
bot/
  config.py       настройки из .env, валидация на старте
  main.py         точка входа: polling локально, webhook на Render
  handlers.py     команды и приём сообщений
  albums.py       склейка альбомов (debounce 2 с по media_group_id)
  categories.py   список категорий для кнопок
  session.py      сессия Telegram с автоповтором при сбоях сети
  pipeline.py     сообщение → свойства и блоки → страница Notion
  notion.py       REST-клиент Notion: data source, страницы, загрузка файлов
  tg_files.py     разбор вложений и скачивание с проверкой лимитов
  archive.py      пересылка вложений в канал-архив и ссылки на них
  social.py       посты Instagram и Facebook через yt-dlp
  article.py      извлечение текста статьи (trafilatura)
  formatting.py   форматирование Telegram → блоки Notion
```

Тонкое место — `formatting.py`. Telegram считает смещения форматирования в
кодовых единицах UTF-16, а Python — в символах; на любом эмодзи вне BMP
разметка съезжает. Модуль строит карту смещений, и это покрыто тестами.

Дедупликация обходится без своей базы: ключ `chat_id:message_id` пишется в
свойство `TG key`, и перед созданием страницы бот ищет его в Notion. Поэтому
эфемерный диск Render ничего не ломает.

## Схема базы

| Свойство | Тип | Содержимое |
|---|---|---|
| Название | title | Заголовок статьи → первая строка текста → имя файла → заглушка |
| Дата | date | Дата исходного сообщения |
| Источник | text | Канал, чат или автор |
| Тип | select | Текст · Ссылка · Фото · Видео · Файл · Аудио · Альбом |
| Ссылка | url | Первая ссылка из сообщения |
| Оригинал в TG | url | Ссылка на исходное сообщение, если её можно построить |
| Категория | select | Раздел, выбранный кнопкой в Telegram |
| Обработано | checkbox | Ручная отметка при разборе инбокса |
| TG key | text | Служебный ключ дедупликации — можно скрыть в интерфейсе |
