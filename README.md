# Telegram → Notion

Личный бот-инбокс: пересылаешь ему сообщение в Telegram — оно становится
отдельной страницей в базе Notion «Telegram Inbox».

Что сохраняется:

- текст с форматированием — жирный, курсив, зачёркнутый, `код`, ссылки,
  цитаты, блоки кода с подсветкой языка;
- фото, видео, кружочки, голосовые, документы (в пределах лимитов, см. ниже);
- альбом из нескольких фото — одной записью, а не пятью;
- по ссылке из сообщения — заголовок, описание и текст статьи;
- источник: канал, чат или автор, плюс ссылка на исходное сообщение.

Повторная пересылка того же сообщения дубль не создаёт.

## Быстрый старт

### 1. Токен бота

Написать [@BotFather](https://t.me/BotFather) → `/newbot` → придумать имя →
скопировать токен вида `123456789:AA...`.

### 2. Интеграция Notion

1. Открыть [notion.so/my-integrations](https://www.notion.so/my-integrations) →
   **New integration**.
2. Тип — **Internal**, воркспейс — свой.
3. Скопировать **Internal Integration Secret** (начинается с `ntn_`).

### 3. Дать интеграции доступ к базе

Это самый пропускаемый шаг. Без него бот получит 404 на своей же базе.

Открыть страницу [**Telegram Inbox**](https://app.notion.com/p/3d7de3e0016c811a81ade80b1a3fe2ca)
→ меню **⋯** в правом верхнем углу → **Connections** → выбрать свою интеграцию.

### 4. Настроить `.env`

```bash
cp .env.example .env
```

Заполнить `TELEGRAM_BOT_TOKEN` и `NOTION_TOKEN`. `NOTION_DATABASE_ID` уже
проставлен. `ALLOWED_USER_IDS` пока оставить пустым.

### 5. Проверить связь с Notion

```bash
python -m pip install -r requirements.txt
```

```bash
python -m scripts.smoke_notion
```

Скрипт создаст в базе тестовую запись с картинкой и закладкой и напечатает
ссылку на неё. Если что-то не так — скажет, что именно. Запись потом можно
удалить.

### 6. Запустить локально

```bash
python -m bot.main
```

Отправить боту `/start` — он ответит твоим Telegram ID. Вписать его в
`ALLOWED_USER_IDS` в `.env` и перезапустить. После этого бот будет отвечать
только тебе, а всем остальным — вежливо отказывать.

## Деплой на Render (бесплатно)

1. Залить проект в репозиторий GitHub (файл `.env` в него не попадёт —
   он в `.gitignore`).
2. На [render.com](https://render.com) → **New** → **Blueprint** → указать
   репозиторий. Render прочитает `render.yaml` и создаст web-сервис.
3. В **Environment** заполнить: `TELEGRAM_BOT_TOKEN`, `NOTION_TOKEN`,
   `NOTION_DATABASE_ID`, `ALLOWED_USER_IDS`.
   `MODE=webhook` и `WEBHOOK_SECRET` подставятся сами.
4. Дождаться деплоя. Адрес вебхука бот выставит сам из `RENDER_EXTERNAL_URL`.

### Чтобы сервис не засыпал

Бесплатный план Render усыпляет сервис после 15 минут без запросов, и первое
сообщение после простоя сохраняется с задержкой 30–60 секунд, пока контейнер
просыпается.

Лечится бесплатным пингом: на [uptimerobot.com](https://uptimerobot.com)
создать HTTP(s)-монитор на адрес сервиса с интервалом 10 минут. Бесплатных
750 часов Render как раз хватает на месяц непрерывной работы.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | Приветствие; в режиме настройки показывает твой Telegram ID |
| `/help` | Справка |
| `/ping` | Проверить связь с Notion и показать лимит на размер файла |
| `/id` | Показать твой Telegram ID |

---

## Лимиты и что с ними делать

| Ограничение | Откуда | Поведение бота |
|---|---|---|
| Файл > 5 МБ | Free-план Notion | Вместо файла — заметка с именем, размером и причиной |
| Файл > 20 МБ | Bot API Telegram | Скачать невозможно; сохраняется карточка с пометкой |
| Пейволл, JS-рендеринг | Сайт статьи | Сохраняются заголовок, описание и ссылка |
| Скрытый автор пересылки | Приватность Telegram | Источник — «Скрытый отправитель» |

Лимит Notion бот узнаёт у API при старте (`/ping` его показывает). Перейдёшь
на платный план — начнёт грузить файлы до 20 МБ без правок кода.

Ссылка на оригинал строится только для сообщений из каналов: для публичных —
обычная `t.me/канал/123`, для приватных — `t.me/c/…`, которая откроется у тебя
как у подписчика. Для пересылок из личных чатов постоянной ссылки не
существует в принципе.

## Как это устроено

```
bot/
  config.py       настройки из .env, валидация на старте
  main.py         точка входа: polling локально, webhook на Render
  handlers.py     команды и приём сообщений
  albums.py       склейка альбомов (debounce 2 с по media_group_id)
  pipeline.py     сообщение → свойства и блоки → страница Notion
  notion.py       REST-клиент Notion: data source, страницы, загрузка файлов
  tg_files.py     разбор вложений и скачивание с проверкой лимитов
  article.py      извлечение текста статьи (trafilatura)
  formatting.py   форматирование Telegram → блоки Notion
```

Тонкое место — `formatting.py`. Telegram считает смещения форматирования в
кодовых единицах UTF-16, а Python — в символах; на любом эмодзи вне BMP
разметка съезжает. Модуль строит карту смещений, и это покрыто тестами.

Дедупликация обходится без своей базы: ключ `chat_id:message_id` пишется в
свойство `TG key`, и перед созданием страницы бот ищет его в Notion. Поэтому
эфемерный диск Render ничего не ломает.

## Схема базы

| Свойство | Тип | Содержимое |
|---|---|---|
| Название | title | Заголовок статьи → первая строка текста → имя файла → заглушка |
| Дата | date | Дата исходного сообщения |
| Источник | text | Канал, чат или автор |
| Тип | select | Текст · Ссылка · Фото · Видео · Файл · Аудио · Альбом |
| Ссылка | url | Первая ссылка из сообщения |
| Оригинал в TG | url | Ссылка на исходное сообщение, если её можно построить |
| Обработано | checkbox | Ручная отметка при разборе инбокса |
| TG key | text | Служебный ключ дедупликации — можно скрыть в интерфейсе |
